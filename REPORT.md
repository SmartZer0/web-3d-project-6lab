## 1. Цель работы

Создать веб-страницу, на которой пользователь может интерактивно рассматривать
3D-модель, вращать её, изменять масштаб и запускать режим дополненной реальности
на совместимом устройстве.

## 2. Использованное программное обеспечение

- Windows;
- HTML5, CSS3 и JavaScript;
- веб-компонент `<model-viewer>` версии 4.0.0;
- Python 3.11.9 и модуль `http.server` для локального запуска;
- 3D-модель `gib.glb` в формате glTF Binary 2.0.

## 3. Краткие теоретические сведения

`<model-viewer>` — веб-компонент для показа моделей glTF/GLB в браузере. Атрибут
`camera-controls` разрешает пользователю управлять камерой, `auto-rotate`
включает автоматическое вращение, а `ar` добавляет возможность передать модель
поддерживаемому механизму дополненной реальности.

Формат GLB объединяет геометрию, материалы, текстуры и другие данные glTF в одном
бинарном файле. Это уменьшает число отдельных сетевых запросов и упрощает
публикацию модели.

## 4. Последовательность выполнения

### Шаг 1. Подготовка файлов

Создан каталог `web-3d-project`. Модель помещена в `assets/gib.glb`.

Валидирован заголовок файла: формат `glTF`, версия 2, заявленный и фактический
размеры совпадают. Размер файла — 1 609 080 байт (примерно 1,53 МиБ). В модели
обнаружены одна сцена, 83 узла, три меша, три материала, три текстуры, два
встроенных изображения и один анимационный клип.

### Шаг 2. Создание HTML-страницы

В `index.html` подключён `<model-viewer>` версии 4.0.0 с Google CDN. Для модели
указаны:

- путь `./assets/gib.glb`;
- альтернативный текст;
- управление камерой;
- автоматическое вращение;
- тень и нейтральное окружение;
- поддержка AR через WebXR, Scene Viewer и Quick Look.

Дополнительно реализованы индикатор загрузки, сообщение об ошибке, кнопки
остановки вращения и возврата камеры к исходному виду.

### Шаг 3. Проверка загрузки

Страница запущена через локальный HTTP-сервер. Выполнены автоматические проверки:

- `index.html` доступен с кодом HTTP 200;
- `assets/gib.glb` доступен с кодом HTTP 200;
- библиотека `<model-viewer>` на CDN доступна с кодом HTTP 200;
- в разметке присутствуют обязательные атрибуты `src`, `alt`,
  `camera-controls`, `auto-rotate` и `ar`.

Перед сдачей необходимо дополнительно открыть страницу в браузере и выполнить
пользовательскую проверку по списку из `README.md`.

### Шаг 4. Настройка внешнего вида

Создан адаптивный интерфейс в едином тёмном стиле. Добавлены заголовок, описание,
контрастная область просмотра, краткая инструкция по управлению и мобильная
компоновка. Высота просмотрщика меняется в зависимости от размера экрана.

### Шаг 5. Подготовка AR

Включён атрибут `ar`, а порядок механизмов запуска задан как `webxr`,
`scene-viewer`, `quick-look`. AR-кнопка показывается компонентом только при
наличии поддержки. Реальный AR-сеанс необходимо проверять на мобильном
устройстве по опубликованному HTTPS-адресу.

### Шаг 6. Подготовка к публикации

Проект не требует сборки и готов для статического хостинга. При публикации
необходимо загрузить `index.html` и каталог `assets`, не изменяя относительный
путь к модели.

## 8. Ответы на контрольные вопросы

**Какие возможности предоставляет `<model-viewer>`?**  
Он загружает модели glTF/GLB, отображает их в браузере, предоставляет управление
камерой, освещение, тени, анимации и запуск поддерживаемых AR-механизмов.

**Зачем использовать GLB или glTF?**  
Это открытый формат, рассчитанный на эффективную передачу 3D-сцен и
поддерживаемый современными веб-инструментами. GLB удобно хранит ресурсы модели
в одном файле.

**Чем маркерный AR отличается от размещения на поверхности?**  
В маркерном сценарии положение модели вычисляется относительно заранее
известного изображения. При размещении на поверхности устройство анализирует
реальное пространство и ставит объект на найденную плоскость. Данная работа
использует второй вариант, если его предоставляет выбранный AR-механизм.

**Почему необходимо тестирование на целевом устройстве?**  
Поддержка WebXR, Scene Viewer и Quick Look зависит от ОС, браузера, камеры,
служб AR и протокола доступа. Проверка только на компьютере не подтверждает
работу мобильного AR.
