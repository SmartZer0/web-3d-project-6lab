# Лабораторные работы № 5–6

Веб-презентация модели `gib.glb` с интерактивным просмотром, анимацией,
визуальными эффектами и AR, выполненная с помощью
[`<model-viewer>`](https://modelviewer.dev/). Модель содержит клип
`Animation` длительностью 16,83 секунды. Для AR на iPhone используется
отдельный файл `assets/gib.usdz`.

## Структура проекта

```text
web-3d-project/
├── assets/
│   ├── gib.glb
│   └── gib.usdz
├── index.html
├── REPORT.md
├── README.md
├── Отчет_ЛР5_model-viewer.docx
├── Отчет_ЛР6_анимация.docx
├── generate_word_report.py
├── generate_word_report_lab6.py
├── screenshots/
│   └── README.md
└── start-server.bat
```

## Быстрый запуск в Windows

1. Дважды щёлкните `start-server.bat`.
2. Не закрывайте открывшееся окно терминала.
3. Откройте в браузере <http://127.0.0.1:8000>.
4. Для остановки сервера нажмите `Ctrl+C` в окне терминала.

Если Windows предложит выбрать приложение для файла `.bat`, откройте терминал
в папке проекта и выполните:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Проверять страницу простым двойным щелчком по `index.html` не рекомендуется:
адрес `file://` может помешать загрузке ресурсов и работе AR.

## Что проверить

- справа сверху появился статус «Модель готова»;
- модель автоматически вращается;
- перетаскивание мышью поворачивает модель;
- колесо мыши изменяет масштаб;
- кнопка «Остановить автоповорот» управляет вращением камеры вокруг модели;
- кнопка «Исходный вид» возвращает камеру в начальное положение;
- временная шкала движется во время воспроизведения;
- кнопки «Пауза» и «Сначала» управляют анимацией;
- переключатель скорости изменяет темп от 0,5× до 2×;
- пресеты «Нейтральный», «Студийный свет» и «Контрастный» изменяют сцену;
- в инструментах разработчика браузера нет ошибок загрузки.

## Публикация и проверка AR через GitHub Pages

GitHub Pages предоставляет необходимый HTTPS-адрес. Не публикуйте весь каталог
`D:\Cursor Projects`: в отдельный репозиторий нужно загрузить только содержимое
папки `web-3d-project`.

### 1. Создание репозитория

1. Войдите на <https://github.com>.
2. Нажмите **New repository**.
3. Введите имя, например `web-3d-project`.
4. Для бесплатной публикации выберите **Public**.
5. Нажмите **Create repository**.
6. В созданном репозитории выберите **Add file → Upload files**.
7. Перетащите содержимое папки `web-3d-project`, включая `index.html` и каталог
   `assets`. Файл должен находиться именно по адресу `assets/gib.glb`.
8. Внизу страницы нажмите **Commit changes**.

`index.html` должен лежать в корне репозитория, а не внутри дополнительной папки
`web-3d-project`. Иначе GitHub Pages не найдёт стартовую страницу.

### 2. Включение GitHub Pages

1. Откройте вкладку **Settings** репозитория.
2. В левом меню выберите **Pages**.
3. В разделе **Build and deployment** установите:
   - **Source:** `Deploy from a branch`;
   - **Branch:** `main`;
   - **Folder:** `/(root)`.
4. Нажмите **Save**.
5. Подождите завершения публикации. Состояние можно посмотреть на вкладке
   **Actions**. Обычно развёртывание занимает несколько минут.

Адрес будет иметь вид:

```text
https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/web-3d-project/
```

Вернитесь в **Settings → Pages** и используйте показанную там ссылку — так вы
избежите ошибки в имени пользователя или репозитория.

Официальная инструкция:
<https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site>

### 3. Обновление уже опубликованного проекта

Если лабораторная № 5 уже размещена на GitHub Pages, новый репозиторий создавать
не нужно:

1. Откройте существующий репозиторий `web-3d-project`.
2. Выберите **Add file → Upload files**.
3. Перетащите обновлённый `index.html` из локальной папки проекта.
4. Если GitHub покажет замену существующего файла, подтвердите её.
5. В поле сообщения укажите, например:
   `Лабораторная № 6: анимация и визуальные эффекты`.
6. Нажмите **Commit changes** в ветку `main`.
7. Дождитесь зелёного результата во вкладке **Actions**.
8. Откройте прежний адрес GitHub Pages и выполните `Ctrl+F5`.

Для исправления AR обязательно замените в репозитории три файла:

- `index.html`
- `assets/gib.glb`
- `assets/gib.usdz`

Word-отчёты для работы сайта не нужны.

### 4. Проверка опубликованной страницы

1. Сначала откройте HTTPS-адрес на компьютере.
2. Дождитесь надписи «Модель готова».
3. Убедитесь, что статус анимации показывает «Воспроизведение · 1×».
4. Проверьте паузу, повторный запуск, временную шкалу и изменение скорости.
5. Переключите все три визуальных режима.
6. Проверьте вращение, масштабирование и отсутствие ошибки загрузки.
7. Нажмите `F12`, откройте **Console** и убедитесь, что нет красных ошибок.
8. Проверьте, что адрес модели открывается напрямую:

```text
https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/web-3d-project/assets/gib.glb
```

### 5. Почему в AR может быть T-поза

Кнопка **Открыть в AR** может запустить один из трёх режимов:

- **WebXR** — AR остаётся в браузере, клип `Animation` продолжает играть;
- **Scene Viewer** — Android открывает отдельное приложение Google и заново
  загружает GLB;
- **Quick Look** — iPhone открывает системный просмотрщик. Автоматический USDZ
  не переносит скелетную анимацию Mixamo, поэтому модель замирает в bind-pose.

T-поза означает, что сработал системный просмотрщик, а не WebXR. Это ограничение
платформы, а не ошибка HTML-страницы.

### 6. Проверка AR на Android

1. Откройте HTTPS-ссылку **непосредственно в Chrome**, не во встроенном браузере
   Telegram, VK или другого приложения.
2. Убедитесь, что установлены актуальные **Google Play Services for AR**.
3. Дождитесь статуса «Модель готова» и воспроизведения анимации на странице.
4. Нажмите **Открыть в AR** и разрешите камеру.
5. Если AR остался внутри Chrome, анимация должна продолжаться.
6. Если открылось отдельное окно Google Scene Viewer, модель может стоять без
   клипа: вернитесь и повторите шаг в обычном Chrome.

### 7. Проверка AR на iPhone или iPad

1. Загрузите в репозиторий не только `index.html`, но и `assets/gib.usdz`.
   Без USDZ iPhone снова покажет T-позу: Safari не умеет WebXR и открывает
   Quick Look, а автогенерация USDZ в `<model-viewer>` анимацию не переносит.
2. Откройте HTTPS-ссылку непосредственно в Safari, не во встроенном браузере
   Telegram или другого приложения.
3. Дождитесь загрузки модели на странице и нажмите **Открыть в AR**.
4. Quick Look должен открыть `gib.usdz` со скелетной анимацией `mixamo_com`.
5. После обновления файлов на GitHub выполните жёсткое обновление страницы.

Документация AR в `<model-viewer>`:
<https://modelviewer.dev/examples/augmentedreality/>

### 8. Как зафиксировать результат

Для отчёта сделайте:

- скриншот опубликованной страницы с видимой строкой HTTPS-адреса;
- скриншот модели с изменённым ракурсом;
- фотографию или скриншот модели в AR;
- запись модели телефона, версии ОС и браузера.

На несовместимом устройстве `<model-viewer>` скрывает AR-кнопку. Это ожидаемое
поведение, а не ошибка страницы.

## Возможные проблемы

- **Модель не появилась:** проверьте, запущен ли сервер и существует ли
  `assets/gib.glb`.
- **Страница без оформления или 3D:** проверьте интернет-соединение —
  компонент версии 4.0.0 загружается с Google CDN.
- **Порт занят:** замените `8000` на `8080` в команде и в адресе браузера.
- **GitHub Pages показывает 404:** проверьте, что `index.html` лежит в корне,
  выбраны ветка `main` и папка `/(root)`, а публикация в **Actions** завершилась.
- **На GitHub Pages нет модели:** проверьте регистр имени `assets/gib.glb`.
  На сервере регистр букв имеет значение.
- **После обновления видна старая версия:** выполните жёсткое обновление
  (`Ctrl+F5`) или подождите обновления кэша Pages.
- **Анимация не запускается:** дождитесь статуса «Модель готова», выполните
  `Ctrl+F5` и проверьте консоль. В GLB должен присутствовать клип `Animation`.
- **В AR модель улетает или её не видно:** загружена старая GLB/USDZ без
  выравнивания по полу. Замените `assets/gib.glb` и `assets/gib.usdz`.
- **Android сразу закрывает камеру:** откройте сайт в Chrome, а не во
  встроенном браузере. На Android теперь сначала запускается Scene Viewer.
- **В AR нет CSS-эффектов страницы:** Scene Viewer и Quick Look являются
  отдельными системными просмотрщиками и не переносят оформление HTML-страницы.
- **AR-кнопки нет:** проверьте HTTPS, браузер, поддержку AR и разрешения
  устройства.
